# AssetToken Purchase 函数集成测试文档

## 测试概述

本测试套件对 `AssetToken` 合约的 `purchase` 函数进行全面的集成测试，使用真实部署的 `CollateralVault` 合约来验证资产代币购买功能的完整性和正确性。

## 测试环境配置

### 部署的合约
- **MockERC20**: 模拟 USDT 支付代币（6位小数）
- **CollateralVault**: 真实的抵押金库合约
- **AssetToken**: 资产代币合约

### 资产参数
- **资产名称**: Test Real Estate Token (TRE)
- **资产总价值**: 1,000,000 USDT
- **募集金额**: 500,000 USDT
- **代币总供应量**: 1,000,000 代币
- **代币价格**: 0.5 USDT/代币

### 测试账户
- **owner**: 合约所有者
- **buyer1, buyer2, buyer3**: 购买者（每人初始 600,000 USDT）
- **provider**: 资产提供方

## 关键发现和注意事项

### 1. 授权机制
买家必须授权 **AssetToken 合约**（不是 CollateralVault），因为 `AssetToken.purchase` 函数调用 `transferFrom` 从买家转移代币到 CollateralVault。

### 2. 精度问题
支付金额计算可能因精度截断而为 0，合约正确拒绝了这种情况。

### 3. 持有者信息设计
每次购买都创建新的 `HolderInfo` 记录，而不是累加到现有记录，这是为了追踪不同时间购买的份额，便于后续分红和清算计算。

### 4. 资金流向
所有购买支付的 USDT 直接转入 CollateralVault，不会停留在 AssetToken 合约中。

### 5. 供应量管理
`remainingMintableSupply` 严格追踪，防止超发。供应量耗尽后，任何购买尝试都会被拒绝。
