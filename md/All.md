**设计者**: Tam

## 项目架构总览

本项目是一个**企业级 RWA（Real World Asset）代币化平台**，支持多种资产类型、灵活分红模型、动态抵押管理、风险评估和自动化清算。

### 核心设计理念

1. **模块化设计** - 每个功能模块独立，便于升级和替换
2. **可扩展性** - 支持多种资产类型和分红模型
3. **安全优先** - 多重安全机制，防止资金损失
4. **自动化执行** - 最小化人工干预，减少操作风险

## 核心合约模块设计

### Layer 1: 基础设施层

#### 1.1 IdentityRegistry（身份注册表）

**核心结构**

- Identity 结构体：onchainId, country, investorType, isVerified, verifiedAt, expiresAt
- 黑名单管理
- 投资者类型分级（个人/机构/合格投资者）

**核心功能**

- registerIdentity() - 注册用户身份
- updateIdentity() - 更新身份信息
- isVerified() - 查询验证状态
- getInvestorType() - 获取投资者类型
- addToBlacklist() - 添加黑名单
- removeFromBlacklist() - 移除黑名单

**关键设计**

- 支持身份过期机制
- 投资者类型分级
- 批量操作支持

---

#### 1.2 AccessController（访问控制器）

**角色定义**

- ADMIN_ROLE - 管理员
- ASSET_PROVIDER_ROLE - 资产提供者
- COMPLIANCE_OFFICER_ROLE - 合规官
- ORACLE_ROLE - 预言机
- LIQUIDATOR_ROLE - 清算者
- EMERGENCY_ROLE - 紧急权限

**核心功能**

- grantAssetProviderRole() - 授予资产提供者角色
- revokeAssetProviderRole() - 撤销资产提供者角色
- hasPermission() - 检查权限

**关键设计**

- 细粒度角色控制
- 紧急权限独立
- 支持角色时间锁

---

### Layer 2: 合规控制层

#### 2.1 ComplianceEngine（合规引擎）

**核心功能**

- canTransfer() - 检查转账是否合规
- canInvest() - 检查投资是否合规
- updateRestrictions() - 更新限制规则

**合规规则**

- 受限国家/地区检查
- 投资限额控制
- 投资者类型分级
- 身份验证状态检查
- 黑名单检查

### Layer 3: 金融层

#### 3.1 CollateralVault（抵押金库）

**抵押模型**

- 基础抵押率: 150%
- 清算阈值: 130%
- 清算罚金: 10%

**计算公式**

```
所需抵押金额 = assetValue × requiredRatio / 10000
当前抵押率 = (collateralAmount × 10000) / assetValue
健康检查 = currentRatio >= LIQUIDATION_THRESHOLD
```

**核心功能**

- deposit() - 存入抵押金
- withdraw() - 提取抵押金
- lockCollateral() - 锁定抵押金
- unlockCollateral() - 解锁抵押金
- calculateRequiredCollateral() - 计算所需抵押金
- isHealthy() - 健康度检查
- getCollateralRatio() - 获取抵押率

---

#### 3.2 TreasuryManager（金库管理器）

**资金管理**

- 资金预留机制
- 平台费用收取（10%）
- 多代币支持
- 资金隔离

**核心功能**

- deposit() - 存入资金
- withdraw() - 提取资金
- reserveFunds() - 预留资金
- releaseFunds() - 释放资金
- collectPlatformFee() - 收取平台费用

---

### Layer 4: 业务逻辑层

#### 4.1 AssetToken（资产代币）

**转账流程**

1. 检查暂停状态
2. 检查冻结状态
3. compliance.canTransfer()
4. identityRegistry.isVerified()
5. 执行转账
6. 更新分红权重

**核心功能**

- transfer() - 转账（带合规检查）
- transferFrom() - 授权转账
- mint() - 铸造代币
- burn() - 销毁代币
- freeze() - 冻结
- unfreeze() - 解冻

---

#### 4.2 DividendModel（分红模型）

**接口设计**

所有分红模型实现统一接口：IDividendModel

**模型 A: 固定收益模型**

- 适用: 债券类资产
- 年化收益率: 8%
- 计算公式: dividend = principal × rate × timeRatio

**模型 B: 阶梯式分红模型**

- 适用: 大额投资者优惠
- 基础收益率: 7%
- 阶梯奖励: 根据持有份额
- 计算公式: dividend = shares × (baseRate + tierBonus) × timeRatio

**模型 C: 风险调整分红模型**

- 适用: 高风险高收益
- 基础收益率: 6%
- 风险溢价: 最高 2%
- 计算公式: dividend = shares × (baseRate + riskPremium) × timeRatio

---

### Layer 5: 执行层

#### 5.1 ExecutionEngine（执行引擎）

**分红分配比例**

- 投资者: 70%
- 资产提供者: 20%
- 平台费用: 10%

**分红执行流程**

1. 预言机报告收益
2. 验证收益数据
3. 计算分红（总收益 × 70%）
4. 计算每个投资者分红
5. 从 Treasury 提取资金
6. 分发给投资者
7. 记录分红历史

**核心功能**

- executeDividendDistribution() - 执行分红分配
- calculateInvestorDividends() - 计算投资者分红
- distributeDividends() - 分发分红
- executeCollateralLiquidation() - 执行清算

---

#### 5.2 RevenueOracle（收益预言机）

**核心结构**
- RevenueData: assetId, revenue, timestamp, source, verified

**多源验证流程（可选增强）**

1. 资产提供者提交收益数据
2. 其他授权 Oracle 确认数据
3. 达到确认阈值（2个确认）
4. 验证通过后，数据可用于分红计算

**核心功能**
- fetchRevenue() - 从链下获取收益数据
- updateRevenue() - 更新链上收益累计总额
- getRevenueData() - 获取收益数据
- isDataValid() - 验证数据有效性

---

#### 5.3 LiquidationManager（清算管理器）

**清算流程**

第1步: 健康度监控 - 当前抵押率 < 130%  
第2步: 触发清算 - 进入宽限期（7天）  
第3步: 分批清算 - 每批 20%，共5批  
第4步: 分配资金 - 优先级：分红 > 本金 > 罚金 > 返还

**核心功能**

- checkLiquidationNeeded() - 检查是否需要清算
- triggerLiquidation() - 触发清算
- executeBatchLiquidation() - 执行分批清算
- distributeLiquidationProceeds() - 分配清算收益

---

#### 5.4 AutomationKeeper（自动化执行器）

**自动化任务**

- 定期获取收益数据（调用 RevenueOracle）
- 定期风险评估（调用 RiskAssessment）
- 定期健康度检查
- 定期分红执行
- 清算监控和触发

**核心功能**

- registerTask() - 注册自动化任务
- executeTask() - 执行任务
- checkUpkeep() - 检查任务是否需要执行
- fetchRevenueData() - 获取链下收益数据
- performRiskCheck() - 执行风险检查
- performHealthCheck() - 执行健康度检查
- triggerLiquidationIfNeeded() - 达到条件时触发清算

---

### Layer 6: 工厂管理层

#### 6.1 AssetFactory（资产工厂）

**资产类型**

- REAL_ESTATE - 房地产
- BOND - 债券
- COMMODITY - 大宗商品
- EQUITY - 股权
- OTHER - 其他

**资产创建流程**

1. 验证提供者身份（KYC + 合格投资者）
2. 风险评估（计算所需抵押率）
3. 创建代币（使用 Clones 模式）
4. 抵押检查（验证足够抵押金）
5. 注册资产（添加到列表）
6. 返回资产地址

**核心功能**

- createAsset() - 创建资产代币
- setAssetConfig() - 设置资产类型配置
- getAllAssets() - 获取所有资产
- getProviderAssets() - 获取提供者的资产

## AutomationKeeper 工作流程详解

### AutomationKeeper 定期任务架构

```
┌─────────────────────────────────────────────────────────────────┐
│              AutomationKeeper 定期任务调度                       │
└─────────────────────────────────────────────────────────────────┘

[Chainlink Automation / 时间触发器]
           │
           │ 每小时触发
           ▼
┌────────────────────────────────────┐
│      AutomationKeeper.checkUpkeep() │
│      检查是否需要执行任务            │
└────────────┬───────────────────────┘
             │
             ├─> 任务1: 收益数据获取（每日）
             │   └─> performRevenueUpdate()
             │       │
             │       ├─> 调用 RevenueOracle.fetchRevenue()
             │       │   ├─ 连接链下数据源
             │       │   ├─ 获取各资产收益数据
             │       │   └─ 验证数据有效性
             │       │
             │       ├─> RevenueOracle.updateRevenue()
             │       │   └─ 更新链上累计收益
             │       │
             │       └─> 调用 AssetToken.updateRevenue()
             │           └─ 将收益数据写入AssetToken
             │
             ├─> 任务2: 风险评估和健康检查（每小时）
             │   └─> performHealthCheck()
             │       │
             │       ├─> 遍历所有活跃资产
             │       │
             │       ├─> 调用 RiskAssessment.assessRisk(asset)
             │       │   ├─ 评估信用风险
             │       │   ├─ 评估市场风险
             │       │   ├─ 评估流动性风险
             │       │   ├─ 计算综合风险分数
             │       │   └─ 计算所需抵押率
             │       │
             │       ├─> 获取当前抵押率
             │       │   └─ CollateralVault.getCollateralRatio()
             │       │
             │       └─> 判断是否健康
             │           ├─ 健康：继续监控
             │           └─ 不健康：触发清算流程
             │
             └─> 任务3: 清算执行（按需触发）
                 └─> performLiquidation()
                     │
                     ├─> 检查宽限期是否结束
                     │
                     ├─> 调用 LiquidationManager.triggerLiquidation()
                     │
                     └─> 执行分批清算
```

## 完整业务流程

### 流程 1: 资产创建和发行

**第1步: 资产提供者准备**
- 通过 KYC 验证
- 获得合格投资者资格
- 准备资产估值报告

**第2步: 存入抵押金**
- 计算所需抵押金（基于风险评估）
- 向 CollateralVault 存入稳定币
- 锁定抵押金

**第3步: 创建资产代币**
- 调用 AssetFactory.createAsset()
- 自动进行风险评估
- 创建 AssetToken 实例
- 配置分红模型
- 铸造代币到资产提供者

**第4步: 开放投资**
- 投资者通过 KYC 验证
- 购买 AssetToken
- 资金进入 TreasuryManager

---

### 流程 2: 收益分配

**第1步: 收益数据获取和上链**
- AutomationKeeper 定期触发（每日/每周）
- 调用 RevenueOracle.fetchRevenue() 获取链下收益数据
- RevenueOracle 将收益数据更新到 AssetToken
- AssetToken 记录累计收益总额

**第2步: 分红计算**
- AutomationKeeper 调用 ExecutionEngine
- ExecutionEngine 从 AssetToken 读取收益数据
- 调用分红模型计算每个投资者分红
- 计算平台费用和提供者收益

**第3步: 资金分配**
- 70% 分配给投资者（按份额比例）
- 20% 分配给资产提供者
- 10% 作为平台费用

**第4步: 记录更新**
- ExecutionEngine 更新 AssetToken 分红状态
- 更新分红历史
- 更新投资者账户
- 发出分红事件

---

### 流程 3: 抵押金清算

**第1步: 健康度监控**
- AutomationKeeper 定期检查（每小时）
- 调用 RiskAssessment 进行风险评估
- RiskAssessment 从 AssetToken 读取抵押信息
- 计算当前抵押率和风险等级
- 如果 < 130%，返回不健康状态

**第2步: 宽限期**
- AutomationKeeper 触发警告
- 通知资产提供者
- 提供者可以补充抵押金
- 宽限期 7 天

**第3步: 启动清算**
- 宽限期后仍不健康
- AutomationKeeper 触发清算
- LiquidationManager.triggerLiquidation()
- 标记为清算状态

**第4步: 分批清算**
- 第1批: 清算 20% 抵押金
- 用于补足未支付分红
- 等待 1 天（避免市场冲击）
- 如果仍不健康，继续下一批
- 最多 5 批（100% 清算）

**第5步: 分配清算资金**
- 优先级1: 补足应付分红
- 优先级2: 偿还投资者本金
- 优先级3: 支付清算罚金（10%）
- 剩余: 返还资产提供者

## 安全机制设计

### 1. 多重身份验证

- 提供者必须 KYC 验证
- 投资者必须 KYC 验证
- 黑名单检查
- 投资者类型检查

### 2. 重入保护

- 所有涉及资金转移的函数使用 nonReentrant
- 遵循 Checks-Effects-Interactions 模式

### 3. 暂停机制

- 支持全局暂停
- 紧急情况可暂停所有操作
- 独立紧急权限

### 4. 时间锁机制

- 关键操作延迟执行（2天）
- 提供时间窗口发现问题
- 可撤销未执行操作

### 5. 多签验证

- 关键操作需要多方签名（3/5）
- 防止单点故障
- 提高安全性

### 6. 上限控制

- 单一资产最大价值: 1亿 USDC
- 单一提供者最大抵押: 5000万 USDC
- 防止过度集中风险

## Gas 优化策略

### 1. 最小代理模式

使用 OpenZeppelin Clones 创建代币实例，节省 90%+ Gas

### 2. 批量操作

支持批量分红分配，减少交易次数

### 3. 存储优化

- 使用 uint256 打包多个值
- 使用 mapping 代替 array（适当场景）
- 使用 immutable 和 constant

### 4. 事件优化

- 关键字段索引
- 减少非必要事件
- 使用紧凑数据类型

## 总结

这是一个**企业级、模块化、安全优先**的 RWA 代币化平台架构，特点：

- **六层架构** - 清晰分层，职责明确
- **安全优先** - 多重安全机制，防止资金损失
- **可扩展** - 模块化设计，支持多种资产和分红模型
- **中心化调度** - AutomationKeeper作为自动化调度中心，统一管理三大核心任务
- **链下数据上链** - RevenueOracle由AutomationKeeper调用，定时获取链下收益数据并写入AssetToken
- **持续风险监控** - RiskAssessment由AutomationKeeper调用，读取AssetToken状态进行风险评估
- **自动化分红** - ExecutionEngine由AutomationKeeper调用，读取AssetToken收益数据执行分红
- **透明可审计** - 完整事件日志，链上可追溯

### 核心创新点：

1. **AutomationKeeper中心化调度架构**：
   - 任务1: 调用RiskAssessment → AssetToken（定期检查风险，必要时清算）
   - 任务2: 调用RevenueOracle → AssetToken（定时将实时收益上链）
   - 任务3: 调用ExecutionEngine → AssetToken（执行定期分红）

2. **AssetToken作为状态中心**：所有工具模块（RiskAssessment、RevenueOracle、ExecutionEngine）都通过读写AssetToken来获取和更新资产状态

3. **动态清算机制**：基于AutomationKeeper驱动的实时风险评估结果，自动触发清算流程，保护投资者利益

此架构可支持房地产、债券、大宗商品等多种 RWA 资产的代币化和管理。
