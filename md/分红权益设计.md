# 订单簿交易中的分红权益设计

## 问题
在订单簿上交易时，出售者的份额转移给买方，但出售者在分红期内仍需获得相应的分红。

## 解决方案：快照机制 + 待分红份额

### 核心概念

1. **分红快照** - 在分红开始前，记录所有持有者当前的份额
2. **待分红份额** - 订单成交时，记录出售者在订单中成交的份额
3. **有效分红份额** = 快照时的余额 + 待分红份额

### 工作流程

```
┌─────────────────────────────────────────────────────────────┐
│ 1. 分红前：创建快照（仅标记分红期开始）                      │
│    assetToken.createDividendSnapshot()                      │
│    → 返回快照ID，不遍历持有者                                │
└─────────────────────────────────────────────────────────────┘
                           ↓
┌─────────────────────────────────────────────────────────────┐
│ 2. 订单成交：记录出售者信息和待分红份额                      │
│    OrderBook.fillOrder()                                    │
│    → recordSellerBalanceAtSnapshot(snapshotId, seller)      │
│    → recordPendingDividendShares(seller, amount)            │
│    → 只记录参与交易的出售者                                  │
└─────────────────────────────────────────────────────────────┘
                           ↓
┌─────────────────────────────────────────────────────────────┐
│ 3. 计算分红：使用有效分红份额                                │
│    dividend = getEffectiveDividendShares(account, snapshotId)│
│    = balanceAtSnapshot[account] + pendingDividendShares[account]
└─────────────────────────────────────────────────────────────┘
                           ↓
┌─────────────────────────────────────────────────────────────┐
│ 4. 分红完成：清除待分红份额                                  │
│    assetToken.clearPendingDividendShares(seller)            │
│    assetToken.finalizeSnapshot(snapshotId)                  │
└─────────────────────────────────────────────────────────────┘
```

### 关键数据结构

#### AssetToken.sol

```solidity
// 分红快照
struct DividendSnapshot {
    uint256 snapshotId;
    uint256 timestamp;
    bool isFinalized;
    mapping(address => uint256) balanceAtSnapshot;  // 快照时的余额
}

// 待分红份额（订单成交后出售者保留的分红权）
mapping(address => uint256) public pendingDividendShares;

// 快照存储
mapping(uint256 => DividendSnapshot) public snapshots;
uint256 public currentSnapshotId;
```

### 关键方法

#### 1. 创建快照（分红前）
```solidity
function createDividendSnapshot() external onlyRole(ADMIN_ROLE) returns (uint256)
```
- 创建新的快照ID
- **不遍历持有者**，仅标记分红期开始
- 返回快照ID供后续使用
- Gas 成本极低

**调用时机**：分红开始前

#### 2. 为出售者记录快照时的余额（订单成交时）
```solidity
function recordSellerBalanceAtSnapshot(uint256 snapshotId, address seller) external
```
- 在 OrderBook.fillOrder() 中调用
- 为出售者记录快照时的余额
- 只在第一次成交时记录（后续成交不重复记录）
- **只记录参与交易的出售者**

**调用时机**：订单成交时（第一次）

#### 3. 记录待分红份额（订单成交时）
```solidity
function recordPendingDividendShares(address seller, uint256 amount) external
```
- 在 OrderBook.fillOrder() 中调用
- 记录出售者在订单中成交的份额
- 出售者可以获得这部分份额的分红
- 支持多次成交累加

**调用时机**：每次订单成交时

#### 4. 获取有效分红份额（计算分红时）
```solidity
function getEffectiveDividendShares(address account, uint256 snapshotId) 
    external view returns (uint256)
```
- 返回账户的有效分红份额
- = 快照时的余额 + 待分红份额
- 用于计算分红金额

**调用时机**：计算分红时

#### 5. 清除待分红份额（分红完成后）
```solidity
function clearPendingDividendShares(address seller) external onlyRole(ADMIN_ROLE)
```
- 分红发放完成后调用
- 清除出售者的待分红份额
- 防止重复分红

**调用时机**：分红完成后

#### 6. 确定快照（分红完成后）
```solidity
function finalizeSnapshot(uint256 snapshotId) external onlyRole(ADMIN_ROLE)
```
- 标记快照为已完成
- 防止后续修改

**调用时机**：分红完成后

### 使用示例

#### 场景：Alice 卖出 100 份给 Bob，分红期间

**初始状态**：
- Alice: 1000 份
- Bob: 500 份

**步骤 1：创建快照**
```solidity
uint256 snapshotId = assetToken.createDividendSnapshot();
// 快照创建，仅标记分红期开始
// 不记录任何持有者信息
```

**步骤 2：Alice 在订单簿上卖出 100 份给 Bob**
```solidity
orderBook.fillOrder(orderId, 100);
// OrderBook 内部调用：
// 1. assetToken.recordSellerBalanceAtSnapshot(snapshotId, Alice);
//    → 记录 Alice 在快照时的余额：1000 份
// 2. assetToken.recordPendingDividendShares(Alice, 100);
//    → 记录 Alice 的待分红份额：100 份
// 
// 结果：
// Alice 的余额：900 份（转给了 Bob）
// Alice 的快照余额：1000 份（记录）
// Alice 的待分红份额：100 份（保留分红权）
// Bob 的余额：600 份
```

**步骤 3：计算分红**
```solidity
// Alice 的有效分红份额
uint256 aliceShares = assetToken.getEffectiveDividendShares(Alice, snapshotId);
// = balanceAtSnapshot[Alice] + pendingDividendShares[Alice]
// = 1000 + 100 = 1100 份

// Bob 的有效分红份额
uint256 bobShares = assetToken.getEffectiveDividendShares(Bob, snapshotId);
// = balanceAtSnapshot[Bob] + pendingDividendShares[Bob]
// = 500 + 0 = 500 份

// 总分红 1000 USDC，按份额分配：
// Alice 分红 = 1000 * (1100 / 1600) = 687.5 USDC
// Bob 分红 = 1000 * (500 / 1600) = 312.5 USDC
```

**步骤 4：分红完成**
```solidity
assetToken.clearPendingDividendShares(Alice);
assetToken.finalizeSnapshot(snapshotId);
// Alice 的待分红份额清除
// 快照标记为已完成
```

### 优势

✅ **公平性** - 出售者在分红期内仍能获得分红  
✅ **Gas 高效** - 快照创建时不遍历持有者，只在交易时记录参与者  
✅ **简洁性** - 无需复杂的权益追踪  
✅ **灵活性** - 支持多次订单成交  
✅ **可审计** - 所有快照和待分红份额都可查询  
✅ **可扩展** - 只记录参与交易的出售者，支持大规模市场  

### 注意事项

⚠️ **快照时机** - 必须在分红开始前创建快照  
⚠️ **待分红清除** - 分红完成后必须清除待分红份额  
⚠️ **权限管理** - 只有管理员可以创建/确定快照和清除待分红份额  
⚠️ **重复分红防护** - 通过 isFinalized 标志防止重复分红  

### 与 OrderBook 的集成

在 OrderBook.fillOrder() 中：

```solidity
function fillOrder(uint256 orderId, uint256 amount) external {
    // ... 验证和支付逻辑 ...
    
    // 转移资产代币给买方
    assetToken.safeTransfer(msg.sender, fillAmount);
    
    // ！记录卖方的分红权益
    uint256 currentSnapshotId = IAssetToken(address(assetToken)).currentSnapshotId();
    if (currentSnapshotId > 0) {
        // 1. 为卖方记录快照时的余额（只在第一次成交时记录）
        assetToken.recordSellerBalanceAtSnapshot(currentSnapshotId, order.seller);
        
        // 2. 记录卖方的待分红份额（每次成交都累加）
        assetToken.recordPendingDividendShares(order.seller, fillAmount);
    }
    
    // ... 更新订单状态 ...
}
```

这样确保了：
1. 买方获得了份额的所有权
2. 卖方保留了这部分份额的分红权
3. 分红时两者都能获得相应的分红
4. 支持卖方多次成交，待分红份额累加
